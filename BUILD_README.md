# LoL Power Rankings — Build & Release Instructions

## What's in this folder

- `launcher.py` — The GUI source (do your edits here).
- `fetch_ranks_gsheets.py` — The analytics CLI (do your edits here).
- `inhouse_tracker.py` — The in-house tracker CLI (do your edits here).
- `credentials.json` — Google service account creds (gets embedded into the .exe).
- `version.txt` — Current version number. **Bump this before each release.**
- `build_merger.py` — Combines sources + creds + API key + version into one `app.py`.
- `build.py` — Runs PyInstaller against `app.py` to produce a one-file `.exe`.
- `app.py` — Generated by the merger; you don't edit this directly.

## First-time setup

You need Python 3.12 or 3.13 (PyInstaller doesn't reliably support 3.14+ yet) plus these packages:

```
pip install pyinstaller gspread google-auth requests
```

Open `build_merger.py` and set `GITHUB_REPO` to your repo (e.g. `"blhei/lol-power-rankings"`) so the auto-update knows where to look for new versions.

## Building the .exe

```
python build_merger.py     # produces app.py
python build.py             # produces dist/LoLPowerRankings.exe
```

That's it. Ship `dist/LoLPowerRankings.exe` to your friends.

## Publishing a new release (auto-update flow)

This is the workflow your friends' .exes will pick up automatically:

1. **Bump `version.txt`** to the new version (e.g. `1.0.1`, `1.1.0`, `2.0.0`).
2. **Run** `python build_merger.py && python build.py` to produce the updated .exe.
3. **Push your source changes** to GitHub (you do this however you normally do).
4. **Create a Release** on GitHub:
   - Go to the repo → "Releases" → "Draft a new release"
   - Tag: `v1.0.1` (must start with `v` and match `version.txt`)
   - Title: e.g. `v1.0.1 — Fix in-house leaderboard sorting`
   - Description (optional but nice): brief release notes — your friends will see these in the update dialog
   - Upload `dist/LoLPowerRankings.exe` as a release asset
   - Click "Publish release"

Within minutes of publishing, friends launching their app will see an "↓ UPDATE TO v1.0.1" pill in the top-right. Clicking it shows the release notes and an "UPDATE NOW" button. They click it; the app downloads, replaces itself, and relaunches. Done.

> The .exe filename in the Release asset must end with `.exe`. The updater finds it by extension, not name.

## Updating the embedded API key

Open `build_merger.py` and edit the `EMBEDDED_API_KEY` constant. Re-run both build steps.

> ⚠️ Riot **dev keys** expire every 24 hours. For long-lived distribution, apply for a Personal API Key or Production Key at https://developer.riotgames.com.

## Updating embedded credentials

Replace `credentials.json` and re-run both build steps.

## How auto-update works under the hood

When the app launches as a frozen .exe, it polls
`https://api.github.com/repos/{GITHUB_REPO}/releases/latest` in the background. If a newer tag is found, it surfaces a clickable update pill. Confirming kicks off:

1. Download the new .exe to a temp folder.
2. Write a tiny batch script that waits for the running app (by PID) to exit, then renames the new file over the current one and relaunches.
3. Spawn the batch script detached.
4. Quit cleanly.

The whole flow is skipped when running from source (i.e. `python app.py`) — the update logic only fires when `sys.frozen` is True.

If something goes wrong mid-update, the user is left with their existing .exe intact (because the swap only happens after a successful download). Worst case: they're stuck on the old version and need to manually download the new one from GitHub.

## Troubleshooting

**"Update Now" downloads but never restarts** — On Windows, the swap depends on the batch script being able to detect when our PID exits. If antivirus quarantines the batch script before it runs, the swap silently fails. Whitelist the temp folder, or check the user's `%TEMP%` for `lolpr_update_*.bat`.

**Friends never see the update prompt** — Check the GitHub repo URL is correctly set in `build_merger.py`. The .exe asset has to end in `.exe`. The release tag has to be a valid version number. Watch for typos like `v 1.0.1` (with a space).

**Update API hits rate limits** — Unlikely for a small group, but GitHub's unauthenticated API allows 60 requests/hour per IP. If you ever exceed that, the update check just fails silently and friends keep using their current version.

**SmartScreen warning on first run** — Expected for unsigned executables. Click "More info" → "Run anyway." Code-signing fixes it but costs money.

**Antivirus flags the .exe** — Common false positive for PyInstaller bundles. The fix is to whitelist the file or buy a code-signing certificate.

## Security reminders

- The .exe contains your `credentials.json` and Riot API key. Anyone with the file can extract them in seconds. **Only share with friends you trust.**
- The auto-update mechanism trusts GitHub. If your GitHub account is ever compromised, an attacker could push a malicious "update" to your friends. Use 2FA on your GitHub account.
- If a key gets compromised: revoke the service account key in Google Cloud Console, regenerate the Riot API key, edit constants, rebuild, publish a release. Friends auto-update within minutes.
